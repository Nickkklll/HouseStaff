# Backend marketplace

Backend интернет-магазина на Node.js и Express. Сервер хранит каталог, заказы и пользователей в JSON-файлах.

## Запуск

Откройте PowerShell в этой папке:

```powershell
cd "d:\STProjects\Ранние работы\market-place\backend"
npm install
npm start
```

После запуска сервер доступен по адресу `http://localhost:3000`. HTTP-события выводятся в эту же консоль в реальном времени: метод, путь, HTTP-статус и длительность запроса. Запросы с ошибками `4xx` выводятся как предупреждения, `5xx` — как ошибки.

Для cookie-запросов frontend по умолчанию разрешен с origin `http://localhost:3001`. Другой origin задайте через `FRONTEND_ORIGIN`.

Для production обязательно задайте секрет JWT:

```powershell
$env:JWT_SECRET = "длинный-случайный-секрет"
npm start
```

Если `JWT_SECRET` не задан, используется тестовое значение из `auth/jwt.js`. Для реального сайта его нужно заменить через переменную окружения.

## Структура файлов

```text
backend/
  server.js                  Главный файл сервера и HTTP-маршруты
  catalog.json               Каталог товаров
  orders.json                Заказы
  userData.json              Пользователи, корзины и избранное
  auth/
    authService.js           Регистрация, вход и хеширование паролей
    jwt.js                   Создание и проверка JWT
    roles.js                 Роли и список разрешений
    userStore.js             Чтение и запись userData.json
  middleware/
    authMiddleware.js        Проверка cookie-токена и прав доступа
    csrfMiddleware.js        Проверка CSRF-заголовка
```

## Как работает авторизация

### Регистрация

```http
POST /auth/register
Content-Type: application/json

{
  "login": "ivan",
  "password": "strong-password",
  "email": "ivan@example.com",
  "name": "Иван",
  "lastName": "Иванов",
  "role": "user"
}
```

При регистрации можно указать роль `user` или `seller`. Новый пользователь получает статус `active`, пустую корзину и пустой список избранного. Роль `admin` через регистрацию недоступна. Ответ содержит:

- `user` — публичные данные пользователя без пароля;
- JWT устанавливается сервером в cookie `access_token` с флагами `HttpOnly` и `SameSite=Lax`.

Пароль сохраняется только в виде bcrypt-хеша в `userData.json`.

### Вход

```http
POST /auth/login
Content-Type: application/json

{
  "login": "ivan",
  "password": "strong-password"
}
```

В ответе сервер устанавливает новую cookie `access_token`. Токен действует до ближайших 00:00 по локальному времени сервера. После этого пользователь должен войти заново.

### CSRF и передача cookie

Перед изменяющими запросами получите CSRF-токен:

```http
GET /auth/csrf
```

Для каждого `POST`, `PATCH` и `DELETE` передавайте значение cookie `csrf_token` в заголовке:

```http
X-CSRF-Token: <значение csrf_token>
```

В frontend-fetch указывайте:

```js
credentials: 'include'
```

`GET /me` возвращает данные текущего пользователя и служит простой проверкой авторизации.

## Роли и права

Полный список находится в `auth/roles.js`.

| Роль | Возможности |
| --- | --- |
| `user` | Смотреть каталог, создавать заказы, смотреть и изменять свою корзину |
| `seller` | Смотреть каталог, видеть свои заказы, изменять свои заказы, добавлять товары, изменять свои товары |
| `admin` | Все возможности, просмотр пользователей, смена ролей, блокировка пользователей, удаление заказов, удаление и скрытие товаров |

Заблокированный пользователь не может войти и не может использовать ранее выданный токен.

## Маршруты

### Авторизация

| Метод | Маршрут | Авторизация |
| --- | --- | --- |
| `POST` | `/auth/register` | Не нужна |
| `POST` | `/auth/login` | Не нужна |
| `GET` | `/me` | Любой активный пользователь |
| `PATCH` | `/me` | Любой активный пользователь; изменяет профиль текущего пользователя |
| `PATCH` | `/me/password` | Любой активный пользователь; меняет пароль текущего пользователя |

`PATCH /me` принимает одно или несколько полей `login`, `email`, `name`, `lastName`, `birthDate`, `phone`. Логин и email должны быть уникальными; дата рождения передаётся в формате `YYYY-MM-DD`; номер телефона — строкой с 7–15 цифрами, допускаются начальный `+`, пробелы, скобки, точки и дефисы. Дату рождения и телефон можно очистить значением `null` или пустой строкой. Пароль и системные данные пользователя этим маршрутом изменить нельзя. Запрос требует авторизацию и CSRF-заголовок.

Сначала войдите через `POST /auth/login` со старым паролем, затем отправьте авторизованный `PATCH /me/password` с новым паролем. Новый пароль должен содержать минимум 6 символов. Маршрут использует cookie-сессию, полученную при входе, и требует CSRF-заголовок.

```json
{
  "newPassword": "new-strong-password"
}
```

Пример тела запроса:

```json
{
  "name": "Иван",
  "lastName": "Иванов",
  "birthDate": "1995-04-18",
  "phone": "+380 50 123 45 67"
}
```

### Каталог и товары

| Метод | Маршрут | Кто может |
| --- | --- | --- |
| `GET` | `/catalog` | Все посетители, включая незарегистрированных |
| `POST` | `/products` | `seller`, `admin` |
| `PATCH` | `/products/:id` | Владелец товара или `admin` |
| `PATCH` | `/products/:id/hide` | `admin` |
| `DELETE` | `/products/:id` | `admin` |

Гости, обычные пользователи и продавцы не видят скрытые товары. Администратор видит их.

### Избранное

У пользователя поле `favorites` содержит ID избранных товаров. У каждого товара каталога есть `favoritesCount` — число пользователей, добавивших его в избранное. Счётчик изменяется только при изменении списка пользователя и не допускает повторного учёта одного пользователя.

| Метод | Маршрут | Действие |
| --- | --- | --- |
| `GET` | `/favorites` | Получить карточки избранных товаров текущего пользователя |
| `POST` | `/favorites/:productId` | Добавить товар в избранное |
| `DELETE` | `/favorites/:productId` | Убрать товар из избранного |

Операции `POST` и `DELETE` применяются через 1 секунду после запроса. Повторное добавление уже избранного товара и удаление отсутствующего товара не меняют список и счётчик. Ответ приходит после обновления профиля и `favoritesCount` в каталоге. Эти маршруты требуют авторизации и CSRF-заголовка для изменяющих запросов.

### Заказы

| Метод | Маршрут | Кто может |
| --- | --- | --- |
| `POST` | `/orders` | `user`, `admin` |
| `GET` | `/orders` | Пользователь видит свои, продавец свои товары, `admin` все |
| `PATCH` | `/orders/:id` | Владелец заказа, продавец связанного товара или `admin` |
| `DELETE` | `/orders/:id` | `admin` |

При создании заказа сервер добавляет `userId`, список `sellerIds` и дату создания. Старые заказы без `userId` не будут отображаться как личные заказы пользователя.

## Фильтрация списков

GET-запросы к `/catalog`, `/orders`, `/users` и `/cart` поддерживают общие query-параметры. Сначала сервер ограничивает данные согласно правам доступа и только потом применяет параметры запроса. Для `/users` по-прежнему требуется роль `admin`.

Для `/cart` параметры применяются к массиву `items`, а `totalAmount` по-прежнему показывает сумму всей корзины. `_fields` принимает имена полей верхнего уровня, разделённые запятыми.

Фильтр по точному значению: `?status=Ожидает`. Несколько фильтров объединяются через AND. Для одного поля можно передать несколько значений, они объединяются через OR.

Для сравнений добавляйте оператор к имени поля: `_eq`, `_ne`, `_gt`, `_gte`, `_lt`, `_lte`, `_between`, `_contains`, `_in`, `_nin`, `_like`, `_exists`. Для вложенных полей используйте точку, например `?customer.name_like=Иван` или `?items.name_like=стул`.

Также доступны `q` для поиска по любому значению записи, `_sort` и `_order` для сортировки, `_fields` для выбора возвращаемых полей, `_page` и `_limit` для нумерации страниц, либо `_start`, `_end` и `_limit` для диапазона. `_limit` ограничен 100 записями. `_page` начинается с 1, `_end` не включается в диапазон.

Примеры:

```http
GET /orders?status=Ожидает&createdAt_gte=2026-09-01&_sort=createdAt&_order=desc&_limit=5
GET /catalog?price_gte=100&price_lte=500&q=стол&_sort=price&_order=asc
GET /orders?items.name_like=стул&_fields=id,status,totalAmount
GET /users?_page=2&_limit=20
GET /catalog?_start=10&_end=20
```

Для `_in`, `_nin` и `_between` значения разделяются запятыми, например `?status_in=Новый,Ожидает` или `?totalAmount_between=100,500`.

### Корзина

| Метод | Маршрут | Кто может |
| --- | --- | --- |
| `GET` | `/cart` | `user` |
| `POST` | `/cart/items` | `user` |
| `DELETE` | `/cart/items/:productId` | `user` |
| `DELETE` | `/cart` | `user` |

Пример добавления товара:

```http
POST /cart/items
Authorization: Bearer <token>
Content-Type: application/json

{
  "productId": 1,
  "quantity": 2
}
```

Ответ корзины имеет вид `{ "items": [...], "totalAmount": 99.98 }`. Каждый элемент
содержит снимок товара в `product`, дату `addedAt`, количество `quantity`, цену за
единицу `unitPrice` и сумму позиции `totalAmount`. Повторное добавление товара
увеличивает его количество. `DELETE /cart/items/:productId` удаляет одну позицию,
а `DELETE /cart` полностью очищает корзину.

### Пользователи

| Метод | Маршрут | Кто может |
| --- | --- | --- |
| `GET` | `/users` | `admin` |
| `PATCH` | `/users/:id/status` | `admin` |
| `PATCH` | `/users/:id/role` | `admin` |

### Адреса пользователя

| Метод | Маршрут | Действие |
| --- | --- | --- |
| `GET` | `/addresses` | Получить адреса текущего пользователя |
| `POST` | `/addresses` | Добавить адрес текущему пользователю |
| `DELETE` | `/addresses/:addressId` | Удалить адрес текущего пользователя |

Для `POST /addresses` передайте JSON с непустыми строковыми полями `country`, `city`, `street` и `number`. ID адресу назначает сервер. Все маршруты требуют авторизации; для `POST` и `DELETE` дополнительно нужен CSRF-токен. Нельзя получить доступ к адресам другого пользователя через эти маршруты.

Для статуса используются значения `active` и `blocked`. Для роли используются значения `user`, `seller` и `admin`.

## Назначение первого администратора

Регистрация всегда создаёт пользователя с ролью `user`. Это сделано намеренно: нельзя получить права администратора, просто добавив роль в запрос регистрации.

После появления первого пользователя его можно назначить администратором вручную в `userData.json`, изменив:

```json
"role": "admin"
```

После этого пользователь должен заново войти и получить новый JWT. Далее администратор сможет менять роли через `PATCH /users/:id/role`.

## Коды ответов

- `201` — объект создан;
- `200` — запрос выполнен;
- `204` — объект удалён;
- `400` — неверные входные данные;
- `401` — отсутствует или недействителен токен;
- `403` — недостаточно прав;
- `404` — объект не найден.

## Важные ограничения текущего хранения

JSON-файлы подходят для учебного проекта и локальной разработки. Для production лучше использовать базу данных, транзакции и отдельное безопасное хранилище секретов. Одновременная запись нескольких запросов в JSON-файл может привести к конфликту данных.
