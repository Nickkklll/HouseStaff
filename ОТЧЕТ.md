## Что сделано

- Добавлена backend-аналитика:
  - `GET /analytics/sales` возвращает число созданных и обработанных покупок, сумму заказов, выручку, количество проданных единиц и средний чек.
  - `GET /analytics/products/top` возвращает рейтинг товаров; продавец получает данные только по своим товарам, администратор может запросить рейтинг конкретного продавца.
  - `GET /analytics/sellers/top` показывает администратору рейтинг продавцов.
  - Для сводки установлен период по умолчанию 30 дней, для рейтингов — шесть месяцев; период можно задать параметрами `from` и `to`.
- Добавлено создание товара продавцом с названием, описанием, категорией, ценой, остатком и загружаемой фотографией. Поддерживаются JPEG, PNG, WebP и GIF размером до 5 МиБ.
- Заказы формируются по актуальным данным каталога. Добавлена проверка количества товара при оформлении заказа.
- При статусе продавца `Обработано` сервер списывает его заказанные позиции со склада. Повторная установка статуса не приводит к повторному списанию; при недостаточном остатке возвращается `409`.
- Для заказа с товарами нескольких продавцов покупатель видит `В обработке`, пока все продавцы не обработают свои позиции.
- Документация backend дополнена описанием аналитических маршрутов, загрузки фото, остатков и статусов.
- Устранена найденная зависимость-уязвимость: `proxy-addr` обновлён с `2.0.7` до `2.0.8`.
- Проверки backend прошли: актуальный набор содержит 12 успешных тестов; проверка синтаксиса и `npm audit --omit=dev` ранее также завершались без ошибок (0 уязвимостей).

### Данные и сценарии заказов

- Указать начальные остатки для существующих товаров: у старых товаров без поля `quantity` проверка и списание остатков не выполняются.
- Проверить полный сценарий покупки и статусов через HTTP API с авторизацией покупателя, продавцов и администратора.

### Отслеживание конверсии

- Сейчас средний чек считается как сумма созданных заказов, делённая на число заказов; он не является конверсией посетителей в покупателей.
- Для расчёта visitor-to-purchase conversion нужно собирать события посещений и определить правила учёта уникальных посетителей и временного окна.
